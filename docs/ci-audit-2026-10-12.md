## Confirmed issues

Ordered by correctness, then security, reliability, maintenance burden, and performance.

### C1. The Discord notify can report an incomplete run as a success (correctness)

Every caller computes:

```
result: ${{ contains(needs.*.result, 'failure') && 'failure' || (contains(needs.*.result, 'cancelled') && 'cancelled' || 'success') }}
```

`needs.*.result` is `success | failure | cancelled | skipped`. A `skipped` job is not caught. If every needed job is skipped, or one is skipped and the rest pass, the action posts nothing on a green-after-green run. On a run after a red one, it posts **RECOVERED** — for a run that did not run the work.

How a job ends up skipped:
- a gate job's `if:` evaluates false;
- a job's `needs` failed while the notify job still runs (`always()`);
- a future path-filtered job is skipped.

The expression is copied into all four repos and the README, so it drifts per repo.

**Fix:**
- The action takes the whole `needs` context (`needs: ${{ toJSON(needs) }}`) and classifies the run itself:
  - any `failure` → failure;
  - else any `cancelled` → cancelled (no post);
  - else any `skipped` → **incomplete** (posts INCOMPLETE naming the skipped jobs, never RECOVERED);
  - else success.
- The FAILED / RECOVERED / manual-PASSED behavior is preserved.
- `result` stays accepted for one release, so callers can migrate.
- The classifier is a script with tests, plus a workflow in this repo that runs them.

### C2. Every repo runs the shared action from `@main` (security, maintenance)

`StarworksDev/.github/actions/discord-ci-notify@main` appears in Arcane, Astra, Manifold2D and Mosaic. Any push to this repo's `main` — including a compromised or mistaken one — changes code that runs in four repos' workflows, with the Discord webhook secret in its environment.

**Fix:**
1. Version the action (tag `discord-ci-notify-v1.0.0` on this repo).
2. Pin every caller to the tag's commit SHA, with the tag name in a comment.
3. Bump callers deliberately when the action changes.

### C5. Fork pull-request workflow approval is "first-time contributors" only (security)

`gh api repos/StarworksDev/<repo>/actions/permissions/fork-pr-contributor-approval` returns `first_time_contributors` for all five repos.

After one merged PR, an outside contributor's later fork PRs run workflows without approval. Today, with only hosted runners and read-only tokens, the impact is CI minutes. Once sub-project B registers a self-hosted GPU runner, the D26 rule applies: fork PRs never reach it, and outside contributors' workflows need approval.

**Fix:**
- Set `all_external_contributors` on all five repos now; it is cheap and no fork PRs exist today.
- B adds the runner-side guards (runner group restricted to named repos/workflows, `push`-only triggers on the GPU job).

### C6. `GITHUB_TOKEN` may approve pull requests (security)

The org setting `can_approve_pull_request_reviews` is **true**, and inherited by `.github`. A workflow could approve its own PR and satisfy review rules.

**Fix:** set it to `false` at the org. No workflow approves PRs.

### C8. Arcane: the build step is the whole cost, and nothing caches compiler output (performance)

Run 38154946856 (main 946092fb, 2 h 52 min wall):

| Leg | Debug build | Release build | Dist build | Test (2 seeds) |
|---|---|---|---|---|
| macos-appleclang (-j2) | **155 min** | 131 | 123 | 10–12 |
| windows-msvc | 25 | **80** | 77 | 6–8 |
| linux-clang-19 | 51 | **79** | 37 | 3–7 |
| linux-gcc-14 | 39 | 68 | 43 | 3–5 |

Every other step is under 1.5 min. macOS is the critical path: 3 vCPU / 7 GB runners at `-j2`, by design (`ci.yml` documents the swap at -j3).

The only lever that cuts this without cutting coverage is a compiler cache:
- ccache for Linux (the CI image of sub-project A ships it) and macOS;
- ccache in MSBuild mode or sccache for MSVC. This needs `/Z7` object debug info (a premake option for CI) and `UseMultiToolTask` so MSBuild invokes `cl` per file. The linker still writes the PDB, so crash symbolization and debuggability are unchanged.

### C9. Arcane: duplicated tool caches waste the 10 GB repo budget (performance)

5.8 GB across 127 caches. The largest are fifteen 326 MB copies of `macos-15-appleclang-<Config>-tools-*`, which hold the premake binary and the Vulkan SDK download.

The SDL3 and tools cache keys include `${{ matrix.config }}`, but their contents are configuration-independent: SDL3 is always built Release, and the downloads are identical. Every macOS run therefore stores three identical copies, multiplied by each PR ref.

**Fix:** drop the config (and compiler) from those keys. This frees the budget C8's compiler caches need.

### C11. Mosaic CI covers one configuration on one OS (coverage)

Mosaic's CI is `windows-latest` Release only. The checked-in `premake5.lua` already carries a Linux filter ("Part B scaffold") and `scripts/generate_linux.sh`. There are no `scripts/build.*` / `run-tests.*` entry points (the shared standard's), no Debug, no sanitizers, and no header self-sufficiency check.

Mosaic's headers already compile on Linux GCC/Clang and macOS inside Astra and Manifold2D (both vendor it), but Mosaic's own tests have never run off Windows.

**Fix:**
- Add Debug on Windows now.
- Add the standard entry points.
- Add Linux GCC/Clang legs only after a local container run passes, so no red or meaningless jobs.
- Add a header self-sufficiency check (Astra's `ci/check-headers.sh` pattern).
- macOS later: the Linux filter's `-mavx2` needs an x86-only guard first.

### C12. Manifold2D: multithreaded code has no sanitizer coverage (coverage)

The tests drive the solver and broadphase through a `std::thread` pool (`tests/BroadphaseMtInvarianceTest.cpp`, `PhysicsContactEventsTest.cpp`). `premake5.lua` has no sanitizer option.

Astra's proven pattern (`--sanitize=address|thread`, Linux clang-19, `ASAN/UBSAN/TSAN_OPTIONS`, a suppressions file) ports directly.

## Proposals (judgment calls)

### P1. Arcane ASan + UBSan lane — recommend, gated on a local triage first

The engine has never run under sanitizers on POSIX (`docs/ci.md` Deviations). Proposed lane:
- Linux clang-19 Debug, in the CI image (which adds `libclang-rt-19-dev`);
- `~[gpu]` CPU suite, under `ASAN_OPTIONS=halt_on_error=1`.

Adding it blind would turn CI red on day one, or invite a `continue-on-error` that hides real bugs. Instead:
1. Run it on the desk through `scripts/ci/local.ps1`.
2. Fix or document (with suppressions) what it finds.
3. Add the lane only when it is green.

LeakSanitizer may need suppressions for SDL / driver singletons. TSan for the job system is a later, separate lane.

### P2. Arcane macOS critical path

After C8, warm runs should be dominated by link and test time. If macOS still gates the run, the options are:
- (a) larger macOS runners (paid; the org is on Free);
- (b) Dist on macOS only on `main` pushes.

(b) trades PR-time coverage, which the brief forbids without cause, so it is **not recommended**. Decide after C8 with measured numbers.

### P3. Astra performance-regression reporting — recommend instruction counts, not wall time

Hosted runner wall-clock varies by tens of percent between runs (shared, heterogeneous hardware), so benchmark timings there cannot gate anything.

Proposal:
- A non-blocking Linux job runs a reduced benchmark profile under `valgrind --tool=cachegrind` and reports instruction counts (Ir), which are stable to well under 1% run to run.
- It compares them with the base branch's last artifact and writes a job-summary table.
- An annotation fires above a threshold (e.g. +3%).

Wall-clock benchmarking belongs on the desk's self-hosted runner (B), on fixed hardware. **Needs the user's go-ahead and benchmark selection; not implemented in this pass.**

### P4. Manifold2D randomized seed — recommend a third, run-number seed

Keep the two fixed seeds (1, 24301): the determinism comparison and the documented reproductions depend on them. Add a third test run whose seed derives from the run number (Astra's `SEED_RUN` scheme). It is printed and in the JUnit file name, so any failure reproduces with `--rng-seed N`.

Its determinism dump is written like the others. `compare-determinism.py` holds trig-free scenes bit-identical across every seed, so the extra seed strengthens the cross-platform check rather than weakening it.

### P5. Compiler caches for Astra / Manifold2D / Mosaic — not justified

Their legs take 1–14 min, and cache restore/save overhead plus budget would eat most of the gain. Revisit if a leg passes ~20 min.

### P6. Shared conventions — standardize, without a shared reusable workflow

The repos already share a written standard (`docs/ci.md`: same section order, entry-point scripts, two seeds, Deviations). A single reusable workflow would force Arcane's image/GPU lanes and Manifold2D's determinism job into one generic shape — **not recommended**.

What to align instead:
- Action versions/SHAs: one table, bumped together.
- `permissions`, `concurrency`, `persist-credentials: false`, timeouts, 14-day retention.
- The notify job: the shared action plus `needs: toJSON(needs)`.
- Seed naming: one fixed seed plus one run-number seed. Arcane's pair is run-number-based on both seeds; its first seed stays because its baselines and docs cite it.
